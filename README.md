# OrbitalGuard 🚀🛰️
> **"Tecnologia espacial salvando vidas na Terra."**

O **OrbitalGuard** é um sistema inteligente de monitoramento e prevenção de desastres naturais (enchentes, deslizamentos e queimadas). Ele conecta dados meteorológicos de satélites, sensores IoT (ESP32) em tempo real e Inteligência Artificial preditiva para alertar populações e órgãos públicos antes que a catástrofe aconteça.

Este repositório contém a **Web API desenvolvida em .NET 9**, responsável pelo ecossistema de dados, regras de negócio e persistência em banco de dados relacional.

---

## 🏛️ Arquitetura e Organização do Projeto

A API foi desenvolvida em C# utilizando o **.NET 9** e o padrão de arquitetura em camadas para garantir escalabilidade, testabilidade e separação clara de responsabilidades.

### Organização de Pastas:
* `📂 Controllers`: Porta de entrada da aplicação. Expõe os endpoints REST e gerencia as requisições HTTP.
* `📂 Models`: Entidades de domínio mapeadas diretamente com as tabelas do banco de dados.
* `📂 Data`: Contexto de dados (`AppDbContext`) que gerencia a comunicação com o banco via Entity Framework Core.
* `📂 Migrations`: Histórico de versionamento do banco de dados.
* `📂 DTOs (Data Transfer Objects)`: Objetos para validação e transferência segura de dados de entrada, impedindo a exposição direta de entidades.

**Justificativa da Arquitetura:** Escolhemos essa estrutura estruturada em camadas porque ela isola as regras de banco de dados das regras de exposição da API. Isso facilita manutenções futuras (como adicionar uma nova funcionalidade ou trocar de banco de dados) sem quebrar o ecossistema existente.

## 📊 Modelagem do Banco de Dados & Diagrama

Atendendo aos requisitos de persistência relacional, implementamos um relacionamento **1:N (Um para Muitos)** entre as entidades `Cidade` e `Sensor`. Uma cidade pode ter múltiplos sensores IoT vinculados monitorando suas áreas críticas.

### Comportamento de Deleção em Cascata (`Cascade`):
Configuramos via Entity Framework que, caso uma `Cidade` seja deletada do sistema, todos os `Sensores` geograficamente vinculados a ela serão **automaticamente removidos em cascata** no banco de dados, garantindo a integridade referencial dos dados e evitando registros órfãos.
